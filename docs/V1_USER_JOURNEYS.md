# MyAvatar V1 user journeys

## Journey 1: first installation

1. User downloads and opens MyAvatar.
2. MyAvatar explains that processing is local and detects hardware.
3. Setup selects Fast or Balanced and explains the choice.
4. Required runtime, models, and voice dependencies install automatically.
5. User tests microphone and speaker.
6. MyAvatar explains optional context permissions in plain language.
7. Seeing Eye starts off and is explained separately.
8. User chooses Nova as the default or selects another bot.
9. The bot introduces itself by voice and begins the first conversation.

Success: a beginner reaches a first voice turn without Terminal, manual paths, or unexplained errors.

## Journey 2: ordinary voice conversation

1. User addresses the active bot.
2. Bot visibly turns attention toward the user and listens.
3. User may pause, correct themselves, or continue speaking.
4. Bot acknowledges, thinks, and responds with natural voice and animation.
5. User interrupts at any point.
6. Bot stops cleanly and returns to listening or ready.
7. Conversation and relevant relationship memories are updated.

Success: the exchange feels live, understandable, and never stuck.

## Journey 3: context-aware interaction

1. User grants a bot access to a relevant source.
2. Bot uses only the permitted context needed for the request.
3. Seeing Eye visibly indicates when screen awareness is active.
4. Bot explains when context materially influenced its response.
5. Meaningful activity may be summarized into activity history.
6. User can inspect, correct, or forget the resulting memory.

Success: context makes the bot more useful without feeling invisible or surveillant.

## Journey 4: proactive presence

1. Bot reacts ambiently to meaningful changes or the user's return.
2. Bot may offer a contextual suggestion or initiate occasionally.
3. User can respond, dismiss, say “not now,” pause, mute, or change proactivity.
4. Bot learns the interaction preference without treating dismissal as rejection.

Success: the bot feels alive and useful without becoming annoying.

## Journey 5: specialist panel

1. User asks the active bot for a specialized task.
2. Bot explains or naturally opens the relevant simple panel.
3. Panel inherits bot identity, voice, memory, permissions, and liveness.
4. User works through a focused flow.
5. Bot remains available for voice conversation and interruption.
6. Result returns to common chat and relationship history.

Panels: Nova/Sterling assistant, Rivit coding, Luma image generation/editing.

## Journey 6: bot delegation

1. Primary bot identifies that another bot can help.
2. User sees a small delegation cue or banner.
3. Specialist receives a scoped task and required context only.
4. Specialist works silently in the background.
5. User sees progress, completion, question, or failure.
6. Primary bot summarizes the result and offers the next action.

Success: collaboration feels like a capable team without an opaque agent swarm.

## Journey 7: memory and forgetting

1. User opens Memory or asks what the bot remembers.
2. MyAvatar shows source, date, bot, category, and confidence where useful.
3. User edits, deletes, clears a category, or says “forget this.”
4. Retrieval index and future prompts no longer use forgotten information.

Success: continuity feels useful and the user remains in control.

## Journey 8: failure and recovery

1. A model, voice, context source, permission, or delegated job fails.
2. Bot remains present and explains the failure plainly.
3. Voice falls back to typed chat or a smaller model where possible.
4. User can retry, stop, repair, revoke, or continue with reduced capability.

Success: no failure leaves the user at a dead end or false-ready state.
